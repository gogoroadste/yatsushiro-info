# やつしろ困りごとまとめ（非公式）

令和8年熊本地震に関する公的機関の発表を、市民の「困りごと」ごとに並べ替えて表示するページです。
情報を作っているのは八代市・社会福祉協議会・熊本県・国の機関で、並べているのがこのサイト、
という関係です。内容は書き換えません。

**リンク先の発表元は、各項目に必ず表示します。** 八代市以外のものには発表元の名前が付き、
リンクの下にも「→ ◯◯のページをひらく」と出ます。非公式サイトが他機関の発表を
市のものであるかのように見せるのは、信頼を損ねる最悪の失敗だからです。

## 公開のしかた（15分ほど）

### 1. リポジトリを作る
GitHubで新しいリポジトリを作ります（**Public**）。名前は `yatsushiro-info` など。

このフォルダの中身をそのまま置いて、push します。

```bash
git init
git add .
git commit -m "初回"
git branch -M main
git remote add origin https://github.com/gogoroadste/yatsushiro-info.git
git push -u origin main
```

### 2. Pages を有効にする
リポジトリの **Settings → Pages** を開き、

- Source: **Deploy from a branch**
- Branch: **main** / **/ (root)**

保存すると数分で `https://gogoroadste.github.io/yatsushiro-info/` が開きます。

### 3. 自動更新を動かす
**Actions** タブを開き、初回だけ「I understand my workflows, go ahead and enable them」を押します。
以降は自動で八代市のページを見に行き、変化があれば `data.json` を更新します。
すぐ動かしたいときは Actions → 「八代市の情報を取り込む」→ **Run workflow**。

## 手で直すところ

### ライフラインの状況ボード
`index.html` 内の `BOARD` と `BOARD_ASOF`。断水やガスが復旧したら書き換えてください。

```js
{k:"水道", v:"おおむね復旧", cls:"ok", note:"一部で濁りが残ります"},
```
`cls` は `bad`（赤）/ `warn`（黄）/ `ok`（緑）。

### 分類がおかしいとき
`scripts/classify.mjs` のキーワードを足し引きし、Actionsを再実行します。
語が長いほど強く効きます（3文字以上=2点、それ未満=1点）。
分類はすべてサーバー側（Actions）で行うため、サイトに手入力する場所はありません。

## 取得先

| 取得先 | 内容 | 落ちたとき |
|---|---|---|
| 八代市 関連情報 | お知らせ全般 | サイト全体を前回の内容で維持し、警告を出す |
| 八代市 緊急情報 | 開設中の避難所 | 避難所の欄ごと消す |
| 八代市社会福祉協議会 | ボランティア・義援金 | 前回の社協分を維持（他は通常どおり動く） |
| 統合幕僚監部 報道発表資料 | 自衛隊の災害派遣（日々の続報PDF） | 前回の自衛隊分を維持 |
| 統合幕僚監部 国内活動 | 今回の地震の専用ページ（作られ次第） | 同上 |

社協サイトはShift-JISのため、文字コードを判定して変換しています。福祉全般を扱うサイトなので、
「災害・ボランティア・地震・義援金・募金・支援・被災」を含む見出しだけを取り込みます。

**自衛隊の災害派遣について**
統合幕僚監部の報道発表から、今回の地震に関するものだけを抜き出します（艦艇の動向など
無関係な発表が大半のため、`熊本地震` と `災害派遣` の両方を含む見出しに絞っています）。
災害ごとの専用ページが作られたら、そちらも自動で拾います。

ただしこれらは**熊本県全体**の活動報告で、八代市民が必要な「どこで水をもらえるか・
どこで風呂に入れるか」は市が発表します。両方を並べる形にしているのはそのためです。

**ガソリンスタンドについて**
資源エネルギー庁の「住民拠点サービスステーション等検索」を常設リンクにしています。
震度5強以上の地震では、エネ庁の災害時情報収集システムが集めた各給油所の営業状況が
地図に出るため、これが唯一の公的なリアルタイム情報源です。停電中でも給油できる
「住民拠点SS」（自家発電設備つき）も分かります。

**コンビニ・スーパーについて**
店舗ごとの営業状況を機械的に取れる公的な仕組みは存在しません。各チェーンは
県単位の休業店舗数を報道発表するだけで、「八代市のこの店が開いているか」は
公開されていません。市が店舗情報を発表すれば自動で「お店・給油」に入りますが、
それ以上は取得できないのが現状です。
店舗ごとの一覧を載せたい場合は、人が確認して手で書く方法しかありません。
古い情報で燃料を使わせて空振りさせるほうが有害なため、推測での掲載はしていません。

**防犯情報について（重要）**
`防犯・詐欺` に載せるのは、**公的機関が出した注意喚起だけ**です。SNSの目撃情報や
未確認情報は取り込みません。ページ内にもその方針を明記しています。

理由は、震災後の「窃盗団がいる」「偽の◯◯がいる」といった話が、日本で繰り返し
誤情報として広まってきたためです。平成28年熊本地震では動物園からライオンが逃げたという
偽投稿で逮捕者が出ました。能登半島地震でも外国人窃盗団の噂が流れ、いずれも
裏付けがありませんでした。関東大震災まで遡れば、流言が虐殺につながっています。

非公式サイトが未確認情報を転載すると、被害を防ぐどころか特定の集団への攻撃を招き、
サイト自体の信頼も失います。不審な人を見かけた場合の正しい行動は「広める」ではなく
「110番・#9110に伝える」なので、ページではそちらへ誘導しています。

**カテゴリと出どころは別の軸です**
カテゴリは「市民の困りごと」で切り、出どころ（八代市・社協・全社協・自衛隊）はラベルで示します。
「自衛隊」というカテゴリを作らないのは、お風呂を探している人が
「自衛隊」の欄を見に行くとは限らないためです。入浴支援は「支援・物資」に入ります。

## 設計で決めたこと

**取得はサーバー側（Actions）で行い、閲覧者のブラウザからは市のサイトを叩きません。**
閲覧者ごとに外部へ取りに行く作りだと、人が集まった瞬間に制限がかかって全員が失敗します。

**取得に失敗しても、前回のデータを残します。**
空のページを配信しないためです。ただし `updated`（取得に成功した時刻）と `checked`（試みた時刻）を
分けて記録し、失敗しているときは画面に黄色い警告を出します。失敗しているのに「最新」と
見えるのが、この種のサイトで最も危険な状態だからです。

**更新の間隔について（重要）**
GitHubの無料枠では、スケジュール実行が混雑時に大幅に間引かれます。`*/10` と書いても
実際には数時間あくことが珍しくありません（実測で3〜4時間あきました）。

そのため次の2段構えにしています。

1. 5分ずらした cron を2つ並べ、発火の機会を増やす
2. 1回の起動の中で4分おきに3回取りに行き、そのつど保存する

それでも間隔は保証されません。サイト側では経過時間に応じて表示を変え、
2時間を超えたら黄色、6時間を超えたら「半日ちかく更新されていない」と明示して
公式ページへ誘導します。**古い内容を新しく見せないことを優先しています。**

急いで最新にしたいときは、Actions → 「八代市の情報を取り込む」→ Run workflow で
すぐに実行できます。

**Actions が赤いときの読み方**
`data.json` の `errors` に理由が入ります。よくあるのは市サイト側のアクセス制限（403）と、
ページ構成の変更（記事リンクが3件未満）です。前者は時間をおいて回復することが多く、
後者は `scripts/fetch.mjs` の抽出部分を直す必要があります。

**避難所一覧が読み取れなかったときは、その欄ごと消します。**
古い一覧を出して、閉まった避難所へ人を歩かせるほうが危険なためです。

**QRコードも自前で描いています。**
外部のQR生成サービスを使うと、通信が細い場所で画像だけ表示されません。JavaScriptで
その場で組み立て、SVGとして描いています（誤り訂正レベルM、型番1〜6）。

**外部リソースをゼロにしています。**
一度開けば電波が切れても同じ画面が残ります。文字サイズは特大まで拡大でき、印刷すると各項目にURLが印字されるので、避難所の掲示にも使えます。

## 広めるとき

- ページ上部にQRコードが自動で出ます（公開URLから生成）。印刷するとQRが42mm角に拡大されるので、そのまま避難所に貼れます
- LINEやXで共有するとタイトルと説明文が出ます（`index.html` の `og:` タグ）
- 市や社会福祉協議会に伝えておくと、誤解が生まれにくくなります。**あくまで市の情報への案内であり、独自の情報は載せていない**点を添えてください
